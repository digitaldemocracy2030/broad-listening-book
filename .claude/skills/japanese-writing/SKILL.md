# 本書の日本語文章ルールによるレビューと推敲

ルール本体は `docs/writing_rules.md`。作業の前に必ず全文を読む。

## 手順

1. 対象ファイルと文責を確認する。`contribution_matrix.md` で担当著者を引く（CLAUDE.md に記載の例外に注意）。作業用ディレクトリ（`wip-nishio/` など）は対象外
2. 機械検査を走らせる
   ```bash
   uv run python scripts/style_lint.py <対象ファイル> --info
   uv run python scripts/style_lint.py --dup   # 章をまたいだ同一文
   ```
3. 原稿を通読し、lint が拾えない項目を見る。特に次の4つ
   - 節末の格言・対句による着地の数（1章1〜2箇所まで）
   - 成功→「ただし」留保の両論併記が毎節同じ位置にないか
   - 主張の範囲と例の範囲が合っているか、因果の機構が書かれているか
   - 見出しと段落先頭文だけを抜き出して読み、論旨が通るか（スケルトン通読）
4. 指摘一覧を出して止まる。修正はまだ適用しない
5. 確認を得てから修正を適用する。文責の異なるファイルはブランチとPRを分ける

## 指摘一覧の形式

ファイルごとに、行番号・ルールの節番号・原文の抜粋・修正案を表で出す。

| 行 | ルール | 原文 | 修正案 |
|---|---|---|---|
| 69 | §6.1 身振り言葉 | ここで重要なのは、ベクトル化によって… | ベクトル化によって… |

表の後に、次の2つを必要な場合だけ付ける。

- 残したもの: AIくさい型に見えるが、意味や論証を担っているので残した箇所と理由
- 書き手に確かめたい点: 意味・事実・意図が確定できず、本文を決められない箇所（推測で書き換えない）

## 書き直すときの禁止事項

- 原文にない数値・固有名詞・因果・評価・読者の感情を足さない
- 推量（「かもしれない」「とみられる」）を根拠なく断定に変えない
- 意味が確定できない語を、近い語に言い換えない。元の語を残して「書き手に確かめたい点」に回す
- 「」内の発言・引用、インタビューの話者行（`**本間：**` など）は書き換えない
- lint の上限を満たすためだけに、別の定型（「〜ではなく」→「〜よりむしろ」など）へ置き換えない。肯定形で直接書く
- 英語版（`en/`、`intro_en.md`）は編集しない。影響がある場合は報告だけする
- 事実関係（日付・数値・固有名詞・条番号）を直す場合は一次情報で裏取りし、ソースを記録する
