# 本書の日本語文章ルール

本書（『政治・自治体・企業に広がるブロードリスニング』）の原稿を書く・推敲する・レビューするときに使う文章規範です。人間の著者とLLM（Claude Code など）の両方を読み手として想定しています。

このルールは、2026年に公開された日本語文章ハーネス4本（末尾の「出典」）を本書向けに統合し、2026年6月のレビュアー指摘「AIくさい」への分析（`ai_smell_report_20260611.md`、未コミットの作業ファイル）の数値目安を組み込んだものです。機械的に数えられる項目は `scripts/style_lint.py` で検出できます。

## 0. 使い方と優先順位

ルール同士がぶつかったら、次の順で優先します。

1. 意味と事実を変えない。推敲で原文にない情報・評価・因果を足さない
2. 事実が正確である（数値・日付・固有名詞・法令。CLAUDE.md の校正ワークフローに従い一次情報で裏取りする）
3. 読者が一度で理解できる
4. AIくさい型の反復を減らす

数値の目安は「この回数を超えたら見直す」という上限で、ノルマではありません。個々の修辞は禁止しません。AI臭の本体は、同じ型が高い密度で繰り返されることにあります。迷ったら「その表現は読者の理解を実際に助けるか」で判断します。

次のものはルールの適用対象外です。

- 取材相手の発言や文献からの引用（「」内、引用ブロック）。話し言葉や原文の表記はそのまま残す
- 固有名詞、正式名称、条文、URL、コード
- 作業用ディレクトリ（`wip-nishio/`、`tokoroten_取材_wip/`、`commented_pdf/`、`transcribe/`）

## 1. 読者と文体

本書の読者は、政治・行政・企業の実務者と、テクノロジーに関心のある一般読者です。専門用語は、機能や現象を平易に説明してから「これを〜と呼ぶ」と名前を渡します。初出で説明した用語は、以後同じ語で通します（「広聴AI」を途中から「ツール」「AI」とぼかさない）。

文体（です・ます／である）は、ファイル単位で統一します。章によって文体が違うのは著者ごとの判断として許容しますが、一つのファイルの地の文で混ぜることはしません。

## 2. 段落と節の構成

段落は論証の一歩です。一段落に一つのトピックを置き、段落の最初の文でその段落が何の話かが分かるようにします。前の段落との関係（因果、逆接、例示）は、段落の先頭の接続表現で示します。

事例章（4〜11章）では経緯そのものが証拠になるので、時系列で書いてかまいません。ただし、主要な結果や数値は節の早い位置で渡し、経緯はその裏付けとして読ませます。「思い込み→異変→種明かし」のような演出で結果を引っ張らないようにします。

因果や経緯は、接続詞でつないだ地の文で書きます。箇条書きを使うのは、項目が同じ文法構造・同じ抽象度で本当に並列なときだけです。見出しの直後に箇条書きが3つ以上並んだら、項目の間に「そのため」「だが」で言える関係が隠れていないかを確かめ、隠れていれば地の文に戻します。

論点は数を先に決めずに、あるだけ書きます。実際は2つしかないものや5つあるものを、3つに丸めないようにします。重要な論点は実例と数値で厚く書き、軽い論点は一言で流してかまいません。すべての項目を同じ厚み・同じ文型で書くと、網羅を装った印象になります。

見出しは、その節が扱う対象か、その節が答える問いを指す句にします。「背景」「まとめ」のような情報のないラベルは避けます。一方で、節の結論を言い切る決め台詞を見出しにすると、読者が本文の前にオチを知ってしまうので、これも避けます。

節や章の結びで、本文の要約を繰り返さないようにします。「以上、〜を見てきた」は削ります。結びには、その節で初めて言える帰結か、次の節へのつながりを置きます。根拠が支える範囲を超えた提言で締めない（「一部の事例」と留保した直後に「すべての自治体が導入すべきだ」と書かない）ことも守ります。

## 3. 論証と事実

事実には出典を添え、意見には「筆者は〜と考える」のように話者を示します。事実の文と意見の文はどちらも「〜だ。」で書けてしまうので、語尾では区別できません。出典を示せない事実は、事実として書かないようにします。

推量や可能性を表す文（「かもしれない」「だろう」「とみられる」）を、根拠なく断定に変えないでください。断定に直してよいのは、本文中の根拠で命題が確定している場合だけです。逆に、確定している事実を「〜と言えるでしょう」とぼかすこともしません。

因果を主張するときは、なぜそうなるのかを一文で示します。複数の要因がある出来事を、一つの原因にまとめないようにします。挙げた例が主張の一部しか支えないなら、主張の範囲を例に合わせて狭めます。

抽象的な主張が3文続いたら、素材が足りない兆候です。固有名詞・年月・人数・件数を集め直します。段落から固有名詞と数字をすべて抜いても文意が変わらないなら、その段落はまだ一般論にとどまっています。素材がないときは推測で埋めず、【要確認】として何を確かめれば書けるかを残します。

「後の章で扱う」と前方参照したら、本当にそこで扱われていることを確認します。章をまたいで、同じ概念の分類や定義を一致させます（ある章で「人間が決める」と書いたことを、別の章で「AIが判断する」と書かない）。

## 4. 文の組み立て

一文には一つの主張を入れます。文の長さは50〜60字を目安にし、100字を超えた文は分けられないかを見直します。ただし、主語や条件を明示したために長くなった文を、文字数だけを理由に縮めて意味を落とすことはしません。

語順は、長い修飾語を先に、短い修飾語を被修飾語の直前に置きます。主語と述語はできるだけ近づけ、「〜な理由は」で始めた文を「〜します」で終えるようなねじれを作らないようにします。

読点は、統語上の切れ目に打ちます。息継ぎのためだけの読点は削ります。二重否定（「ないわけではない」）は肯定形に直します。「の」で名詞を3つ以上つなげた句（「市の意見募集の結果の分析」）は、動詞を入れて開きます。

同じ文末（「〜です。」「〜ます。」）が何文も続く単調さは、文の長短を混ぜて崩します。イ形容詞に「です」を付けた文（「難しいです」「多いです」）が出たら、文がそこで孤立している兆候なので、前後の流れごと書き直します。

接続詞は、効力の及ぶ範囲に合うものを選びます。対比関係にない二つの事柄を「一方」でつながないでください。「しかし」が連続したら、本当の対立点がどこかを決め直します。「さらに」「また」「加えて」を連打しないようにします。

## 5. AIくさい型の密度

ここに挙げる型は、1回なら問題ありません。同じ型が高い密度で繰り返されたときにAI臭が出ます。

| 型 | 例 | 上限の目安 |
|---|---|---|
| 否定してから言い直す構文 | 「単なるXではなくY」「Xだけでなく、Yも」 | 1章2回 |
| 説明調の着地 | 「〜のです。」「〜のだ。」 | 1節2回 |
| 修辞疑問の自問自答 | 「では、〜でしょうか？　それは〜だからです」 | 1章1回 |
| 節末の格言・対句による着地 | 「見えにくい声を、見える論点へ。」 | 1章1〜2箇所 |
| 太字ラベル付きの3点セット箇条書き | 「**第一に**…**第二に**…**第三に**…」 | 1章1箇所 |
| 太字 | 文中の強調 | 1節1〜2箇所 |
| 同じ鋳型の連続 | 書き出しが「2020年に〜。2022年に〜。2024年に〜。」 | 3回続けない |

否定してから言い直す構文は、読者が実際に誤解していそうな場面でだけ使います。見分け方は、後半だけを読ませて意味が通るかです。「実際は発注そのものを止める仕組みだ」は単独で成り立ちますが、「有用だ」は前半の否定と対になって初めて強調に見えるので、言い換えにすぎません。

節末の着地は、事実・数字・引用で終わる節を混ぜます。格言や対句で終わる節が続いていたら、少なくとも半分は事実で終わらせます。

成功を述べた直後に「ただし〜という課題もある」と留保を置く両論併記を、毎節同じ位置に入れないようにします。留保を書くなら、その後で論を進めます。逆接で終えて宙吊りにしないでください。

うまく書けた言い回しを、章内や章をまたいでコピーしないでください。同じ主張を二度目に出すときは、前の箇所を参照するか、表現を変えます（2026年6月の分析では「合意の地図を描くのはAI、進路を決めるのは人間」がほぼ同文で複数章に出ていました）。`scripts/style_lint.py --dup` で全原稿の重複文を検出できます。

## 6. 語彙

### 6.1 前置き・身振り言葉

「注目すべきは」「重要なのは」「特筆すべきは」「見逃せないのが」「ここで注目したいのは」のような、これから言うことの重要さを予告するだけの前置きは使いません。指す内容をそのまま主語にして書きます。

- 修正前: 「注目すべきは、回答の7割が自由記述だった点です。」
- 修正後: 「回答の7割が自由記述でした。」

同じ理由で、「本章では〜を見ていく」「〜について掘り下げる」「深掘りする」のような予告も削り、扱う内容そのものから書き始めます。章冒頭で扱う範囲と対象読者を示す案内は残します。

### 6.2 空虚な形容・姿勢の宣言

次の語は、主張の中身の代わりに強調や網羅の感触だけを足します。使うなら、何がどう不可欠なのか、どの観点から見たのかを書きます。

- 空虚な形容: 「不可欠」「核心的」「鍵となる」「本質的」「多角的」「包括的」「総合的」
- 姿勢の宣言: 「正面から扱う」「真摯に向き合う」
- 決め文: 「〜に他ならない」「〜と言っても過言ではない」「これこそが〜だ」「〜と言えるでしょう」

### 6.3 増幅語と展望の決まり文句

「劇的に」「飛躍的に」「計り知れない」「画期的」「驚くほど」「目覚ましい」は、数字や事実が併記されているなら削ります。数字がないなら、数字を探して書きます。章末の「未来の一端を垣間見せる」「時代はすでに動き始めている」のような展望の決まり文句も、具体的な次の出来事に置き換えます。

### 6.4 比喩でぼかす語

2026年の日本語ネット記事で急増した比喩や評価語は、何を指すかを書けるなら具体的に書きます。

- 理解を曖昧に表す語: 「解像度を上げる」「腹落ち」「言語化」「粒度」（データの粒度など技術用語としての用法は残す）
- 質感を装う語: 「手触り」「肌感」「体温」「熱量」「温度感」
- 役割の比喩: 「入口」「土台」「両輪」「〜のカギ」「勝ち筋」「刺さる」
- 作業を曖昧に表す動詞: 「落とし込む」「紐解く」

定着した慣用句（「骨が折れる」「車の両輪」）や、本書で定義した術語（「合意の地図」など）は残します。判断に迷ったら、AIが広まる前の人の文章でもふつうに見かける言い方かどうかを目安にします。

### 6.5 硬い言い回し

「〜を実現することができます」は「〜できます」、「〜することによって」は「〜して」「〜すれば」に縮めます。「活用する」「実施する」は、行政文書の引用や制度名でなければ「使う」「行う」で足りることが多いです。

## 7. 翻訳調

英語の構文を日本語の語順に置き換えただけの文は、文法的に正しくても読みにくくなります。

| 型 | 修正前 | 修正後 |
|---|---|---|
| 無生物主語＋他動詞 | 「このデータは需要の変化を示している」 | 「このデータから、需要が変化していると分かる」 |
| 英語慣用句の直訳（carry / open / live） | 「ベクトルが選好を運ぶ」「この問いは開かれている」 | 「選好がベクトルに反映される」「この問いにはまだ答えが出ていない」 |
| 話し言葉の比喩動詞 | 「この手法が効く」「地味に効いてくる」 | 「この手法を使うと〜が改善する」 |
| can の直訳 | 「短縮することができる」 | 「短縮できる」 |
| in terms of の直訳 | 「コストという観点から見ると」 | 「コストで見れば」 |
| have の直訳 | 「大きな意味を持つ」 | 「大きな意味がある」 |
| 関係節の積み重ね | 「多くの自治体が導入を進めているが効果を実感できていないという課題を抱える技術」 | 文を二つに割る |

モデルやデータを主語にして意思を持つように書く擬人化（「AIは民意を知っている」）は、人か処理を主体に戻すか、「〜から分かる」「〜に含まれる」の形に言い直します。

## 8. 記号と表記

ダッシュ（「——」「―」「──」）で文をつながないでください。補足は括弧（）に入れるか、句点で文を区切るか、接続詞でつなぎます。英語の em dash の直訳で、LLMが生成した日本語に特に多い記号です。

- 修正前: 「意見が出なくなるまで——つまり議論が収束するまで——続けた。」
- 修正後: 「意見が出なくなる（議論が収束する）まで続けた。」

絵文字や装飾記号は使いません。太字は第5節の上限に従います。

用語・表記の統一は次を参照します。

- CLAUDE.md の「用語・表記の決定事項」（「クエスチョン」「We connect」「政務調査会」など、個別に確定した表記）
- `99_付録_用語集.md`（本書の術語の定義）

## 9. AIに推敲させるときの作法

LLMにレビューや書き直しをさせる場合は、上のルールに加えて次を守ります。

- 意味を保持する。原文にない数値、固有名詞、因果、評価、読者の感情を足さない。意味が確定できない語は、近い語へ言い換えずに元の語を残す
- 不明点は本文で推測せず、「書き手に確かめたい点」として書き手に返す
- 指摘と適用を分ける。まず指摘一覧を出し、確認を得てから修正する（CLAUDE.md の校正ワークフロー）
- 文責（`contribution_matrix.md`）ごとに修正を分ける
- 引用・発言は書き換えない
- 英語版（`en/`、`intro_en.md`）は編集しない。日本語側の変更が英語版に影響する場合は報告だけする

仕上げには、見出しと各段落の先頭文だけを抜き出して通読します。論旨が通るか、同じ書き出しの型が3回続いていないか、節ごとに濃淡があるかは、この骨組みだけで判定できます。

## 10. 機械検査

```bash
# 章ごとの検査（book_order.txt の全ファイル）
uv run python scripts/style_lint.py

# 特定ファイルだけ
uv run python scripts/style_lint.py 02_ブロードリスニングとアンケートの違い、定量分析から定性分析へ.md

# 全原稿をまたいだ同一文の検出
uv run python scripts/style_lint.py --dup

# 件数の一覧だけ
uv run python scripts/style_lint.py --summary
```

lint が拾うのは数えられる型だけです。格言着地、両論併記、論証の飛躍、濃淡の欠如は人が読んで判断します。lint の指摘がゼロでも、AIくさくない保証にはなりません。
